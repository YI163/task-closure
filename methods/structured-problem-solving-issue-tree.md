## 1. 解决什么问题

面对笼统、结论不明的难题（如「竞品研究从哪下手」「业绩为什么没达标」），不知道该先查什么、问题到底出在哪一层。

**预期结果**：一棵层级化问题树：主问题→子问题→可查证的末级问题；互斥且合起来覆盖主要可能（MECE），并标出关键假设与查证优先级。

## 2. 什么时候用 / 什么时候不要用

### 前置条件（应全部满足才使用）

- 能用一句话写出待回答的主问题（或至少能给出候选表述）
- 存在可获取的信息源（数据、文件、访谈、实测），能在期限内核验部分子问题
- 允许「先假设再验证」，不要求一次给出完整答案
- 有明确的时间预算用于拆分与查证

### 不适用（出现任意一条就换方法或降级为轻量清单）

- 目标清楚、步骤已知（如「按清单把行李装好」）——直接给行动清单成本更低
- 问题本质是执行遗漏而非判断困难（如「忘了提交表格」）——补一个动作即可，不需要问题树
- 没有任何可获取的信息源，拆分出的叶节点无法被核验——应先取得信息或降低目标
- 时限极短（例如 15 分钟内要答复）——拆分的时间成本超过收益
- 用户已明确指定了方法与答案，只需要执行与确认——再拆树属于机械套框架

## 3. 输入与输出

**输入**

- 原始任务描述与提问者/使用者
- 目标与成功标准初稿
- 已知事实、假设、未知清单
- 可用来源与查证时间预算
- 约束（时间、权限、预算、隐私）

**输出**

- 问题树（主问题→子问题→可查证叶节点）
- 每个叶节点的查证计划（查什么、去哪里、多久）
- 关键假设清单与验证优先级
- 结论草稿：被支持/被推翻/仍未确认三类分开

## 4. 执行步骤

1. 把任务改写成可回答的主问题，先与提问者确认问题表述本身是否就是要解决的问题
2. 用 1–3 条候选假设作为树的骨架，而不是平铺所有可能性
3. 对每条假设做 MECE 拆分：子问题互不重叠、合起来覆盖主要可能，并检查是否漏掉整类
4. 把叶节点写成可查证的问题（能对应数据、来源或一次访谈），无法查证的继续下拆
5. 按「影响 × 可查证性」排序，先只做 3–5 个最关键叶节点
6. 记录查证结果并回看树是否仍成立；不成立就修订树并保留变更说明
7. 输出结论并区分：已核验事实 / 来源观点 / 推断 / 尚未确认

## 5. 检查表（做完逐条核对；不能打勾就写「未核验」）

- [ ] 主问题能用一句话写出，且与「真正想解决的问题」一致，而不是被要求的动作
- [ ] 同一层子问题之间举不出同时属于两者的例子（互斥）
- [ ] 每个叶节点都能对应一个具体来源或一次查证动作，而不是「再想想」
- [ ] 至少标出一条关键假设，并写明若被推翻会改变哪个决定
- [ ] 结论区分为已核验事实、来源观点、推断、尚未确认四类

## 6. 模板（可直接复制到任务记录或对话中填写）

```text
主问题（一句话）：____________________________________________

假设 H1：______________________________________________________
  ├─ 叶节点 Q1.1（可查证的问题）：______________________
  │    查证方式：□ 数据 □ 文件/来源 □ 访谈 □ 实测   负责人：____  截止：____
  │    结果：________   状态：□ 已核验事实 □ 来源观点 □ 推断 □ 未确认
  └─ 叶节点 Q1.2：______________________________________
假设 H2：______________________________________________________
  └─ 叶节点 Q2.1：______________________________________

已排除的可能（及排除依据）：____________________________________
关键假设：____________  若被推翻 → 影响：____________
结论：______________________________________________________
```

## 7. 失败处理

| 失败情形 | 处理动作 |
|---|---|
| 拆不动或越拆越乱 | 回到主问题改写；若仍不行，说明缺的是信息不是结构，改为先做一次探索性资料扫描或访谈 |
| 发现两个子问题重叠 | 合并或重新界定，不允许保留两套口径 |
| 查证后发现方向错了 | 保留原树作为变更记录并重画一版，写明改动原因，不静默替换 |
| 树越画越大、时间耗尽 | 冻结在当前深度，只带走 3–5 个关键叶节点与结论，其余标为待查 |
| 只有 AI 参与、没有用户确认 | 在计划中标注「问题表述未经用户确认」，并把需要确认的问题列出 |
