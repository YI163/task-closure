# 计划-执行-检查-处理循环（PDCA；Deming 变体 PDSA）

- `method_id`: `pdca`
- 索引：`methods/index.json`（本文件是正文，JSON 是机器可读索引）
- `verification_status`: `unverified` ——框架的公开来源已在线核验；本条目步骤尚未在真实任务中执行验证，未验证范围见 §8
- 最近更新：2026-10-14（来源核验原始输出：`reports/METHOD_RESEARCH.md`）

## 1. 解决什么问题

面对「怎么做才有效还不知道」的任务（如调整作息、试新工作流程、改进写作方法），一次性大计划容易方向错误且无法从结果学习。

**预期结果**：一个短试验循环：小范围试一次 → 用事先定好的指标看结果 → 保留有效部分、修正或放弃无效部分，并把结论写回计划或经验库（未验证的只能记为待验证假设）。

## 2. 什么时候用 / 什么时候不要用

### 前置条件（应全部满足才使用）

- 任务允许迭代，单次小试验的代价可接受
- 能定义至少一个可观察的结果指标（可以粗糙，但要事先写好）
- 有进入下一轮的机会（时间/资源允许）
- 失败可承受且不产生不可逆后果

### 不适用（出现任意一条就换方法或降级为轻量清单）

- 不可逆或高风险的一次性动作（提交申请、发布公告、医疗决策）——不能试错，应用检查表/阶段门
- 没有第二次机会的一次性事件（婚礼当天、只此一次的考试）——应做预案与彩排
- 反馈周期远长于任务期限（例如三个月才知道效果）——先做研究与决策，并明确说明本任务内无法验证
- 步骤已知的纯执行任务——按清单执行更省成本
- 指标完全无法观察（无数据、无人记录）——此时 PDCA 会退化为「凭感觉打勾」

## 3. 输入与输出

**输入**

- 当前做法与要改善的问题
- 可观察指标与观察方式（谁记录、多久看一次）
- 试验规模与时间盒
- 约束与安全边界（哪些结果不可接受）

**输出**

- Plan：假设 + 本轮改什么 + 预期观察到的变化
- Do：实际做了什么、与计划的偏差
- Check：指标实际值 vs 预期，差异及可能原因
- Act：采纳/调整/放弃的结论，以及下一轮计划或经验库候选条目

## 4. 执行步骤

1. Plan：写成「如果做 X，就会观察到 Y」的假设，并选 1–3 个指标
2. Plan：把本轮限定在一个时间盒与一个小范围（如先试一周、只改一个环节）
3. Do：按计划执行，并如实记录偏差（不美化、不补记成功）
4. Check：对比预期与实际，并区分「指标没变」与「没按计划做」两种情形
5. Act：给出采纳/调整/放弃结论；有效做法固化为标准，无效做法记下原因
6. 决定是否进入下一轮；未观察到结果的结论只能写入经验库的 to_verify

## 5. 检查表（做完逐条核对；不能打勾就写「未核验」）

- [ ] 指标在本轮开始前就已写下（不是事后挑一个好看的指标）
- [ ] 执行记录包含与计划的差异，而不只是「完成了」
- [ ] 结论区分「数据支持 / 主观感觉 / 尚未确认」
- [ ] 一次只改一个变量，或明确说明多变量同时改导致无法归因
- [ ] 写回经验库的条目必须有 observed_outcome 证据；未执行/未观察到的只能标 to_verify（对应 T09）

## 6. 模板（可直接复制到任务记录或对话中填写）

```text
Plan（本轮开始前写下）
  假设：如果 ________________，就会观察到 ________________
  指标（1–3 个）：____________  观察方式/频率：____________
  时间盒：____________  范围限制：____________

Do：实际执行 ________________  与计划的偏差：____________

Check：指标实际值 ________ vs 预期 ________
  差异可能原因：____________  属于：□ 指标没变 □ 没按计划做 □ 无法观察

Act：□ 采纳（固化为标准做法） □ 调整（下一轮改什么） □ 放弃（原因）
  写回经验库？□ 否（无新经验是合法结果） □ 是（必须有 observed_outcome 证据；否则只能 status=to_verify）
```

## 7. 失败处理

| 失败情形 | 处理动作 |
|---|---|
| 指标没变化 | 先确认是否真的按计划执行，再检查指标敏感度与时间长度；不要直接宣布方法无效 |
| 出现负面结果 | 记录并评估是否立即停止；涉及安全、隐私或第三方利益时优先止损 |
| 无法观察结果 | 如实标注「本轮无法验证」，不用感觉替代证据 |
| 多轮循环无结论 | 回到问题树重新确认要解决的核心问题 |
| 用户中途改变目标 | 追加 changes 并重置本轮假设，不沿用旧指标冒充结论 |
