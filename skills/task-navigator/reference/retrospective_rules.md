# 复盘与经验沉淀规则（reference）

依据：`spec/03_SKILLS_AND_EXPERIENCE_MEMORY.md` §6/§7/§8/§9，验收 T08/T09/T10/T12。

## 1. 复盘只回答五个实用问题

1. 原目标与完成标准是什么？实际结果如何？
2. 哪些计划步骤**真的**有帮助，哪些是浪费？
3. 发生了什么意外？根因是什么（**事实与推测分开写**）？
4. 哪些技能**确实被验证**了，哪些仍有缺口？
5. 是否有值得未来复用的经验？适用条件和反例是什么？

**不是每个任务都必须新增经验。** 无新经验是合法且常见的结果，不要为凑数而写。

## 2. 写入前的七道门禁（缺一不可）

| # | 门禁 | 不过关的处理 |
|---|---|---|
| 1 | 是否真有跨任务价值？ | 只是这次的特殊情况 → 不写 |
| 2 | 事实 / 解释 / 假设是否分开？ | 混在一起 → 拆开或标 `to_verify` |
| 3 | 是否与已有经验重复或冲突？ | 重复 → 合并或补充证据；冲突 → 标冲突并保留两条 |
| 4 | 是否保存了源任务与结果证据？ | 无 → `source_task_id` 必填，缺则不得写入 |
| 5 | 状态是否与证据强度匹配？ | 单次观察 → `single_observation`；未执行 → `to_verify` |
| 6 | 敏感信息是否已最小化？ | 工作机密原文 → 只保留去敏后的通用原则 |
| 7 | 是否真的值得长期保存？ | 不确定 → 不写 |

## 3. 状态阶梯（只能按证据爬）

```
to_verify ──(真实执行且有结果证据)──> single_observation ──(再次独立复现)──> repeatedly_supported
     ▲                                        │
     └────────── challenged_by_counterexample ◀┘        obsolete（环境已变）
```

- **计划从未执行** → 只能 `to_verify`。禁止写「此方法显著提升效率」这类结果性结论（T09）。
- `observed_outcome.executed` 必须如实为 `false`。
- 单次成功永远是 `single_observation`，**不得**升级为普遍规律。
- 有反例时必须记进 `counterexamples`，并把状态改为 `challenged_by_counterexample`，而不是删掉反例。

## 4. 检索与使用（T08/T10）

1. 从**目标、领域、任务类型、约束、当前问题**提取检索线索，不是只拿标题匹配。
2. 只取少量最相关经验，**不把整个库塞进上下文**。
3. 排序同时考虑：任务相关性、条件匹配、证据质量、重复验证、时间新鲜度、**负面反例**。
4. 把经验当**建议或检查点**，不得覆盖当前任务已核实的事实。
5. 使用时必须说明：**采用了哪条、为什么适用、边界在哪**。条件不符就明确说「这条不适用，因为…」。
6. 经验与当前事实冲突 → 优先核实，不盲目套用。
7. 冲突或过时的经验：**不随机挑一条当事实**，比较上下文与证据，必要时重新研究或标为未知，并在任务决策中保留不确定性。

## 5. 隐私与领域隔离（T12）

- 三类范围：`personal` / `work` / `general`。
- **公司机密不得提炼进通用经验**：只保留去敏、可泛化的原则（例如「跨部门取数要先确认口径」而不是具体指标与数值）。
- 长期存储只保留：任务连续性、未来复用、用户明确要求所必需的信息。
- 用户必须能查看、修正、导出、删除自己的经验与技能记录。
- 外部分享、云同步、向外发送记忆**不属于默认行为**，需要用户明确授权。
