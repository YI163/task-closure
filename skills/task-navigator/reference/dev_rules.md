# 开发规范（改脚本/校验规则时读）

> 这些不是「任务执行」的规矩，是「改本项目代码」的规矩。
> 2026-10-15 做减法时从 SKILL.md §I-2 移出——它此前占我每次开工的注意力，
> 但只在改代码时才需要。

## 新增任何校验规则时的强制动作

**新规则写完不算完成，必须当场做反向测试**：造一个违规样本，证明它会失败。

**为什么单列这条**（实测两次）：
- 规则只注册名字没实现检查 → 「看起来有护栏，实际没有」
- 规则的实现里有个 `except Exception: pass`，吞掉了 `NameError`（缺 `import json`）
  → **规则从不执行，而所有测试都通过**。是自己手工重放每一步才发现的。

**动作清单**：
1. 造违规样本 → 跑校验 → 必须非零退出且报出该规则名
2. 捕获异常时不得静默 `pass`——把异常本身作为错误报出
3. 若确实要静默（如读可选元数据失败无危害），在代码里写明为什么无害
