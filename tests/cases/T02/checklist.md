# T02 判定要点：模糊任务能抓关键未知

- 来源：spec/04_ACCEPTANCE_TESTS.md §2 T02
- 输入：`tests/cases/T02/input.json`（「帮我研究一下家里买什么净水器比较好。」）
- 证据目录：`reports/evidence/T02/`
- 模式：模型判断类 → 自动断言只覆盖「数据结构是否承载了关键未知」，**不自动宣布通过**，交由独立审查员判定。

## 通过标准（spec/04 原文）
1. 识别需要了解的关键条件（预算、家庭用水需求、安装条件、所在地区/供水情况等）；
2. 只问会显著改变选择的少量问题，或标注假设并先给研究框架；
3. 区分已知、未知和需要核实的内容；
4. 不在条件未知时直接给出无依据的唯一结论。

## 判定方式
| 要点 | 自动化断言 | 需独立审查员判定 |
|---|---|---|
| 1 关键条件 | unknowns ≥ 3 且覆盖 预算/用水/安装/地区 四类（编号 UN-*，含 why_it_matters 与 how_to_verify） | 是否抓住真正会改变结论的条件 |
| 2 少量问题/先给框架 | assumptions 非空且计划步骤齐备（说明先给了框架） | 问题数量是否克制、是否把用户困在问卷里 |
| 3 已知/未知/待核实 | unknowns 字段结构（含 how_to_verify）；无「推断当事实」的 evidence 记录 | 输出文本是否区分了四类信息 |
| 4 不早给唯一结论（负向） | `decisions` 为空（未在条件未知时锁定结论）；无单一推荐结论字段 | 文本中是否存在无依据的唯一推荐 |
