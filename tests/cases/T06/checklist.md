# T06 判定要点：任务进度能够恢复

- 来源：spec/04_ACCEPTANCE_TESTS.md §2 T06
- 输入：`tests/cases/T06/input.json`、`done_s1.json`、`bad_step_no_evidence.json`、`blocker.json`、`decision.json`、`unknown.json`
- 证据目录：`reports/evidence/T06/`

## 通过标准（spec/04 原文）
1. 能识别当前任务和最近状态；
2. 不要求用户重新提供全部背景；
3. 准确列出已完成、未完成、阻碍和下一步；
4. 不把未验证完成的步骤标为完成。

## 判定方式
| 要点 | 自动化断言 | 需独立审查员判定 |
|---|---|---|
| 1 识别任务与状态 | `task_show.py --task <id>` 退出 0，输出含任务编号/标题/状态/进度 | 状态描述是否准确 |
| 2 不要求重讲背景 | 输出含「原始请求（用户原话，未经改写）」区块 | 是否真的做到了不追问背景 |
| 3 列出已完成/未完成/阻碍/下一步 | 输出分别含：已完成步骤及证据、未完成步骤、阻碍、未解决的问题/未知项、已做的决定、计划变更、下一步 | 列出内容是否与实际状态一致 |
| 4 不把未验证步骤标为完成（负向） | 无证据 `step` 必须被拒（exit 2）；重复标记必须被拒；未完成步骤不出现在 completed_steps | — |

## 负向断言（必须真检查）
- `task_update.py step` 缺 evidence → 拒绝；
- 同一步骤重复标记 → 拒绝；
- 未验证完成的步骤不得出现在 `completed_steps`。
